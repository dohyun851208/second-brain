# Second Brain — 나처럼 판단하는 AI 만들기

내가 LLM과 신중하게 나눈 대화에는 나의 선택, 거절, 수정 요청이 그대로 남아 있습니다.
**Second Brain**은 그 흔적에서 판단 기준을 증류해, 새 작업에서 "일반적으로 좋은 답"이 아니라
**"나라면 선택할 답"**을 만들어주는 개인화 볼트 시스템입니다. Claude Code와 Codex에서 모두 작동합니다.

## 구조 — 8층 볼트

| 층 | 역할 | 접근 |
|---|---|---|
| `0_원본/` | **내가 만든** raw 데이터 — md는 물론 **hwp·hwpx·pdf·docx·xls·xlsx·png·jpg·webp 그대로** (이름 자유) | 평소엔 안 읽음 |
| `1_파싱/` | 원본 전체의 Markdown 변환본 (kordoc 엔진 자동 생성 — 손대지 않음) | 드릴다운·증류 입력 |
| `2_두뇌/` | 증류된 판단 규칙 + 팩트카드 (원문 인용·출처 링크 동봉) | 작업의 판단 기준 |
| `5_규범자료/` | **남이 만든 것 중 한 글자도 바꾸면 안 되는 것** — 성취기준·지침·법령 | 인용할 때. 없으면 지어내지 않고 물음 |
| `6_참고자료/` | **남이 만든 것 중 재구성해도 되는 것** — 교재·남의 수업안·연수 자료 | 재료가 필요할 때. 쓰면 출처 표시 |
| `7_개인정보이미지/` | 서명·도장·신분증·통장사본·증명사진 — 픽셀 원형을 유지해 문서에 재사용 | 컴파일 제외, 승인된 문서 작업 시 |
| 지휘자 | `AGENTS.md`(본문) + `CLAUDE.md`(한 줄 임포트) — 요청마다 필요한 모듈만 로드 | 항상 |
| `8_시스템/` | 두뇌 제작·갱신 도구 (파서·컴파일러 프롬프트, 갱신 절차, 이력 로그) | 두뇌 갱신 시 |
| `9_형식/` | Kordoc 기반 hwp/hwpx·xls/xlsx 작업 + 서명·도장 HWPX 실측 배치 | 해당 형식 작업 시 |

문서 파싱·편집에는 [chrisryugj가 개발한 kordoc](https://github.com/chrisryugj/kordoc)을 사용합니다. kordoc은 별도의 오픈소스 프로젝트이며 **MIT 라이선스**로 배포됩니다.

파이프라인: `0_원본`(아무 형식) →파싱→ `1_파싱`(전부 md) →증류→ `2_두뇌`(판단 규칙).
파싱과 증류는 각각 승인 후 실행되며, 사이에서 변환 품질을 직접 검수할 수 있습니다.

**어디에 넣을지는 "누가 만들었나"로 갈립니다.** 내가 만든 것(내 수업안·내 글·대화·이력서)은 `0_원본/`으로 가서
판단 규칙이 됩니다. 남이 만든 것은 증류하지 않습니다 — 남의 판단이 내 두뇌에 섞이면 안 되니까요.
대신 파싱만 해서 5·6층에 두고 필요할 때 찾아 씁니다. 가르는 질문 하나: **"내 말로 바꿔 쓰면 틀린 게 되나?"**
예면 `5_규범자료/`, 아니면 `6_참고자료/`.

| | 파싱 | 증류 | 원문 |
|---|---|---|---|
| `0_원본/` | O | **O** | 요약해도 됨 (그게 목적) |
| `5_규범자료/` | O | X | **한 글자도 못 바꿈** |
| `6_참고자료/` | O | X | 재구성 허용 |
| `7_개인정보이미지/` | **X** | X | **픽셀 원형 유지** |

이미지는 용도로 나눕니다: **읽어서 지식화할 이미지 → `0_원본/`, 형태 그대로 쓸 개인정보 이미지 → `7_개인정보이미지/`**.
후자는 OCR·컴파일하지 않습니다.

## 준비물

1. 볼트로 쓸 빈 폴더 하나 (옵시디언 볼트 권장). `0_원본/`을 미리 만들 필요는 없습니다.
2. 초기화 뒤 LLM 대화 내보내기(md), 이력서, 내가 쓴 수업안·글, OCR할 스캔 이미지 등 **내가 만든 것**을 `0_원본/`에 투입 — 파일명 자유, 분류 불필요 (구형 `.doc`만 `.docx`로 재저장)
3. 교육과정 성취기준·교육청 지침은 `5_규범자료/`, 교재·남의 수업안·연수 자료는 `6_참고자료/`에 투입
4. 서명·도장·신분증·통장사본·증명사진은 `7_개인정보이미지/`의 해당 폴더에 투입

> 특히 좋은 재료: 결과물이 마음에 안 들어 여러 번 고친 대화, 선택지 중 하나를 고른 대화.
> 학생 이름·학번·성적·상담 내용은 익명화해서 넣으세요.

## 시작하기

가장 쉬운 설치는 사용하는 Codex나 스킬 설치를 지원하는 에이전트에게 저장소 주소와 요청을 그대로 주는 것입니다.

> https://github.com/dohyun851208/second-brain 이 스킬 설치해줘.

링크 설치를 지원하지 않는 환경에서만 다음 명령을 사용합니다.

```powershell
# Codex
git clone https://github.com/dohyun851208/second-brain "$env:USERPROFILE\.codex\skills\second-brain"

# Claude Code
git clone https://github.com/dohyun851208/second-brain "$env:USERPROFILE\.claude\skills\second-brain"
```

1. 볼트로 쓸 폴더를 열고 Codex 또는 Claude Code를 실행합니다. 이 **현재 폴더**가 볼트가 되므로 고정된 경로는 없습니다.
2. **"세컨드브레인 세팅해줘"** → 이름을 한 번 확인하고 구조를 자동 생성합니다. `AGENTS.md`와 `CLAUDE.md`는 설정 과정에서 반드시 설치됩니다. 기존의 다른 `AGENTS.md`가 있으면 덮어쓰지 않고 충돌을 알려줍니다.
3. **"컴파일해줘"** → 형식 문서 자동 md 파싱 → 대화 분석 → 확인 질문 몇 개 → 나만의 두뇌 v1.0
   (파싱만 먼저 해서 변환 품질을 훑어보고 싶으면 **"파싱해줘"** → 검토 → **"증류해줘"**)
4. 끝. 이후 이 폴더에서 여는 모든 세션은 자동으로 나의 두뇌를 사용합니다.
   스킬은 더 필요 없고, Codex도 `AGENTS.md`를 읽어 동일하게 작동합니다.

## 일상 사용

- **검수·선택**: "이 수업안 검수해줘" → ①선택 ②왜 나다운가 ③수정 예상 지점 ④수정안 ⑤확인 필요
- **한글·엑셀**: 볼트에서 실행하면 다른 폴더의 hwp/hwpx/xlsx도 처리합니다. 일반 HWP/HWPX는 Kordoc만 사용하며, 처리하지 못하는 파일은 원본을 그대로 둡니다. 서명·도장 HWPX 배치만 한컴 렌더 실측 스크립트를 사용합니다. 완성본은 원본 옆에 `_완성본`으로 저장되고 원본은 덮어쓰지 않습니다.
- **성취기준·지침 인용**: 문서에 성취기준 코드나 지침 문장이 필요하면 `5_규범자료/`에서 원문 그대로 가져오고 출처를 붙입니다. **볼트에 없으면 지어내지 않고 물어봅니다** — "5~6학년군 성취기준이 없습니다. 넣어주시겠어요, 아니면 그 칸만 비울까요?"
- **참고자료 활용**: `6_참고자료/`의 교재·남의 수업안을 재료로 쓰면 결과물에 출처와 "두뇌 규칙 근거 없음"이 표시됩니다. 내 판단이 아닌 부분이 어디인지 보이게 하려는 것이고, 내 규칙과 부딪치면 내 규칙이 이깁니다.
- **양식 완성**: "이 신청서 작성해줘" → 양식 필드 + `2_두뇌`의 사실·판단 + `7_개인정보이미지`의 필요한 자산을 종합합니다. 민감 이미지를 실제로 열거나 삽입하기 전에는 사용 예정 항목을 확인하며, "이 문서에 서명까지 넣어줘"처럼 특정 자산을 명시하면 그 범위는 승인으로 처리합니다.
- **두뇌 성장**: 새 대화·문서를 `0_원본/`에 넣어두면 다음 세션 시작 때 자동 감지 → 승인하면 파싱·증류로 두뇌가 갱신됩니다.
- **세션 되돌리기**: 오늘 대화가 숙고할 만했다 싶으면 "이 대화 저장할 만해?"라고 물어보세요. 두뇌가 저장 후보를 제안하고, 저장 여부는 직접 정합니다(자동 저장은 하지 않습니다 — 단순 승인은 후보가 아닙니다).
- **성장 제안**: 증류가 끝나면 두뇌가 "어떤 영역이 얇으니 이런 자료를 넣으면 좋다"고 제안합니다 — 넣을지는 자유이고, 안 넣어도 아무것도 깨지지 않습니다.
- **교정**: 결과가 "나답지 않다"고 말하면 해당 규칙이 수정되고 이력이 남습니다.

## 개인정보

이 저장소에는 빈 템플릿(구조)만 있으며 누구의 개인 데이터도 포함하지 않습니다. 실제 볼트는 사용자가 선택한 위치에만 저장됩니다.
OneDrive 같은 동기화 폴더를 선택하면 `7_개인정보이미지/`도 해당 서비스에 동기화되므로 계정 보안·공유 설정을 확인하세요.

저장소의 `.gitignore`는 저장소 루트의 로컬 테스트 문서·미리보기와 템플릿 안에 실수로 넣은 개인정보 이미지를 Git 추적 대상에서 제외합니다.
파일을 암호화하거나 삭제하는 기능은 아니며, 별도 위치에 만든 실제 볼트에는 그 볼트의 보안·백업 정책이 적용됩니다.

## 업데이트

스킬 폴더에서 `git pull` 후, 볼트에서 **"세컨드브레인 업그레이드"** — 시스템 파일만 갱신되고 내 원본·두뇌·이력은 보존됩니다.
kordoc은 호환 메이저(`@^4`) 안의 최신판을 실행 시 사용합니다. 새 메이저는 자동 전환하지 않고 변경 기록·대표 문서를 검증한 뒤 세컨드브레인 시스템 지침과 함께 올립니다.
구버전(v1, 4층 구조) 볼트는 업그레이드 때 폴더 재배치가 자동 안내됩니다 — 원본·두뇌 내용은 그대로 유지됩니다.
v2(6층) 볼트는 `5_규범자료/`·`6_참고자료/`가 빈 템플릿으로 추가되며, `0_원본/`이나 `2_두뇌/`에 남의 자료가 섞여 있으면
이동을 **제안**합니다(자동 이동하지 않습니다). 기존 파싱본 이름(`수업안.hwp.md`)도 새 규칙(`수업안.md`)으로 개명할지 물어봅니다.
