# 파서 프롬프트 (원본 → md 변환)

> `0_원본/`·`5_규범자료/`·`6_참고자료/`의 모든 형식을 Markdown으로 1차 변환하는 절차.
> 이 파일이 파싱 절차의 정본이다. 증류(`컴파일러-프롬프트.md`)는 항상 `1_파싱/`만 입력으로 삼는다.
>
> **권장 사고 수준: 낮음.** 절차와 형식별 도구가 아래 표로 고정돼 있어 판단할 것이 거의 없다.
> 여기서 나는 실패는 판단 오류가 아니라 **단계 누락**(images 폴더 개명, 대장 갱신)이므로,
> 사고량을 늘리기보다 아래 절차를 빠짐없이 지키는 데 집중한다.

## 원칙

- `0_원본/`은 불변 — 어떤 경우에도 수정·이동·개명하지 않는다. `5_규범자료/`·`6_참고자료/`의 원본도 같다.
- `7_개인정보이미지/`는 입력이 아니다. 탐색·OCR·파싱·대장 등록을 하지 않는다.
- `1_파싱/`은 재생성 가능한 파생물이다. 손으로 고치지 않는다 (재파싱하면 덮어써진다). 내용이 틀렸으면 원본을 고치고 재파싱한다.
- 파싱은 기계적 변환이다 — 내용을 요약·해석·정리하지 않는다. 그것은 증류(컴파일러)의 몫.
- 파싱 실행은 사용자 승인 후. 실패는 조용히 건너뛰지 않고 보고한다.

## 절차

### 1. 대상 선별

**`0_원본/`** 전체(하위 폴더 포함, `_` 시작 파일 제외)를 `2_두뇌/index.md`의 "원본 반영 대장"과 대조해 찾는다:
① 대장에 없는 새 파일 ② 수정시각이 대장 기록과 달라진 파일 ③ 대장에 있지만 파싱본이 없는 파일.

**`5_규범자료/`·`6_참고자료/`**는 대장을 쓰지 않는다. 같은 폴더에 짝이 되는 `.md` 파싱본이 없거나
원본 수정시각이 파싱본 frontmatter의 기록보다 새로우면 대상이다 (`_` 시작 파일, `_지난판/`은 제외 —
지난판은 사용자가 명시적으로 요청할 때만 파싱한다).

이미지 파일명이 서명·도장·신분증·통장사본·증명사진 등 **원형 재사용 개인정보 이미지**로 보이면 파싱하지 말고
`7_개인정보이미지/`로 분류할지 사용자에게 확인한다. 사용자가 OCR 목적이라고 확인한 경우에만 `0_원본/` 입력으로 처리한다.

### 2. 형식별 변환 (도구: `9_형식/`)

| 원본 형식 | 방법 |
|---|---|
| `.md` · `.txt` | 그대로 복사 (내용 무변경, 파일명은 아래 저장 규칙을 따른다) |
| `.hwp`(3.x/5.x) · `.hwpx` · `.pdf` · `.docx` · 구형 `.xls` | kordoc으로 Markdown 추출 (`npx -y kordoc@^4`, 사용법: `9_형식/references/kordoc.md`) |
| `.png` · `.jpg` · `.jpeg` · `.webp` | 텍스트·지식 추출 목적 이미지에 한해 kordoc 직접 입력 — 로컬 한글 OCR 자동 적용 |
| `.xlsx` | openpyxl로 시트 → Markdown 표 (`9_형식/references/workflows/xlsx-forms.md`) |
| 암호 문서 | Kordoc이 지원하는 HWPX·HWP3·HWP5는 `--password`로 파싱. 암호는 응답·로그·frontmatter에 기록하지 않음 |
| 한컴 DRM·손상 파일·미지원 구조 | 자동 우회하지 않음 — 원본을 그대로 두고 실패 사유 기록 |
| 구형 `.doc` | 미지원 — 사용자에게 `.docx` 재저장을 요청한다 |

kordoc을 쓰는 배치는 시작할 때 `npx -y kordoc@^4 --version`을 한 번 실행해 실제 버전을 기록한다.
kordoc은 **한 파일씩 실행하고 출력명을 직접 지정**한다: `npx -y kordoc@^4 <원본> -o <파싱본 경로>`.
일괄 모드(`-d`)는 쓰지 않는다 — `수업안.hwp`·`수업안.pdf`가 공존할 때 충돌 검사 없이 서로 덮어쓴다
(아래 명명 규칙의 충돌 처리가 건너뛰어진다).

스캔·손상 PDF는 최초 파싱의 품질 신호나 경고가 `needsOcr`를 가리키거나 결과가 비정상적으로 비어 있으면
`--ocr`로 다시 파싱한다. 이 옵션은 필요한 페이지만 로컬 PP-OCRv5로 인식한다. 텍스트층 자체가 잘못돼
자동 판정이 놓친 경우에만 `--ocr-force`를 쓴다. 수식 OCR은 별도 `--formula-ocr`이며 필요할 때만 켠다.
2단 시험지처럼 테두리 박스가 표로 오인되어 읽기 순서가 뒤집힌 경우에만 `--no-tables`로 다시 파싱한다.
이미지가 매우 많은 문서의 구조화 JSON이 필요하면 `--format json --image-refs`를 `-o`와 함께 사용한다.

### 3. 저장 규칙

**위치** — 파싱본은 그것이 소비되는 곳에 둔다:

| 원본 위치 | 파싱본 위치 | 이유 |
|---|---|---|
| `0_원본/` | `1_파싱/` 아래 같은 상대 경로 | 소비처(증류)가 다른 층에 있어 넘겨준다 |
| `5_규범자료/` · `6_참고자료/` | **원본 바로 옆** (같은 폴더) | 소비처가 그 자리(조회·인용)라 나갈 이유가 없다 |

5·6층 파싱본을 `1_파싱/`으로 보내지 않는다. 거기는 증류 입력층이라, 증류 금지 파일이 섞이면
폴더로 계약을 나눈 의미가 사라진다.

**파일명** — **원본의 확장자를 `.md`로 교체**한다 (`수업안.hwp` → `수업안.md`).
같은 폴더에 `수업안.hwp`와 `수업안.pdf`가 함께 있어 이름이 충돌하면, 나중에 파싱하는 쪽만
`수업안(pdf).md`처럼 원본 확장자를 괄호로 덧붙여 구분한다. 충돌이 없으면 괄호를 붙이지 않는다.
어떤 원본에서 왔는지는 frontmatter의 `원본:` 필드가 담당하므로 파일명이 확장자를 짊어질 필요가 없다.

5·6층의 원본이 이미 `.md`면 **그 파일 자체가 파싱본**이다. 사본을 만들지 않고 frontmatter도 넣지 않는다
(원본 불변). 메타데이터는 그 폴더의 `자료목록.md`가 담당한다.

**이미지** — kordoc이 파싱본 옆 `images/`에 `image_001.png`식으로 저장하는데, 번호가 문서마다 1부터라
그대로 두면 다음 문서가 덮어쓴다. **각 파일 파싱 직후, 다음 파일로 넘어가기 전에**:
① `images/` → `<파싱본 이름(.md 제외)>.images/`로 개명 (예: `수업안.images/`)
② 파싱본 안의 `](image_` 링크를 `](<파싱본 이름>.images/image_`로 치환 (kordoc은 `-o` 모드에서 링크에 폴더 접두사를 안 붙인다).
base64 인라인(`--inline-images`)은 md가 비대해져 증류 입력에 부적합 — 쓰지 않는다.

**frontmatter** — 파일 맨 위에:

```yaml
---
원본: <0_원본/상대경로 | 같은 폴더의 원본 파일명>
원본-수정시각: <mtime>
파싱일: <YYYY-MM-DD>
도구: kordoc | 복사 | openpyxl
도구-버전: <kordoc이면 실제 --version | 그 외 실제 도구 버전 또는 copy>
---
```

5·6층 파싱본에는 **계약 줄을 추가**한다. 파일이 실수로 옮겨지거나 복사돼도 자기가 무엇인지 들고 다니게 하는 장치다:

```yaml
계약: 규범 — 원문 고정 · 증류 금지 · 요약 금지     # 5_규범자료/
계약: 참조 — 재구성 허용 · 증류 금지 · 출처 표시 의무  # 6_참고자료/
범위: <자료목록.md의 범위와 같은 값>                # 5_규범자료/만
```

### 4. 검수 안내 (증류 전 확인 지점)
표·서식이 많은 hwp/pdf는 변환 손실이 날 수 있다. 변환을 마치면 사용자에게 알린다:
"`1_파싱/`의 변환본을 열어 내용이 온전한지 훑어보세요 (특히 표와 이미지 링크). 이상 없으면 '증류해줘'라고 하면 됩니다."
5·6층을 파싱했으면 그 폴더의 변환본을 가리켜 같은 안내를 한다 (증류가 없으므로 "증류해줘" 문구는 뺀다).
별도의 검수 절차·체크 항목은 두지 않는다 — 안내까지가 파서의 몫이고, 확인 여부는 사용자가 정한다.

### 5. 대장·목록 갱신
- `0_원본/` 출신: `2_두뇌/index.md` 원본 반영 대장에 파싱본 경로·파싱일을 기록한다. 반영처는 증류 전이므로 비워 둔다.
- `5_규범자료/`·`6_참고자료/` 출신: 대장에 **등록하지 않는다** (증류 대상이 아니므로 반영처가 영원히 빈 칸으로 남아 증류 필요로 오인된다). 대신 해당 폴더 `자료목록.md`의 파싱본 칸을 채운다. 새 자료라 행 자체가 없으면 사용자에게 범위·상태를 물어 한 행을 추가한다 — 5층은 **범위**가 비면 인용 판단(있다/없다)을 할 수 없으므로 반드시 채운다.

## 예외 상황

- **파싱 실패** (암호 미제공·불일치, 한컴 DRM, 깨진 파일, 미지원 형식) → COM 변환·직접 XML·다른 파서로 자동 우회하지 않는다. 원본을 그대로 두고 대장 파싱본 칸에 "실패: 사유"로 기록한 뒤 사용자에게 알린다. 암호 자체는 어디에도 기록하지 않는다.
- **원본이 삭제된 파싱본 발견** → 사용자에게 알리고, 동의받아 파싱본과 대장 항목을 정리한다 (딸린 `<원본 파일명>.images/` 폴더 포함).
- **이미 반영처가 있는데 파싱본만 없는 항목** (v1 마이그레이션 직후) → 파싱본만 만들어 대장을 채운다. 재증류하지 않는다.
