# 파서 프롬프트 (원본 → md 변환)

> `0_원본/`의 모든 형식을 `1_파싱/`의 Markdown으로 1차 변환하는 절차.
> 이 파일이 파싱 절차의 정본이다. 증류(`컴파일러-프롬프트.md`)는 항상 `1_파싱/`만 입력으로 삼는다.

## 원칙

- `0_원본/`은 불변 — 어떤 경우에도 수정·이동·개명하지 않는다.
- `1_파싱/`은 재생성 가능한 파생물이다. 손으로 고치지 않는다 (재파싱하면 덮어써진다). 내용이 틀렸으면 원본을 고치고 재파싱한다.
- 파싱은 기계적 변환이다 — 내용을 요약·해석·정리하지 않는다. 그것은 증류(컴파일러)의 몫.
- 파싱 실행은 사용자 승인 후. 실패는 조용히 건너뛰지 않고 보고한다.

## 절차

### 1. 대상 선별
`0_원본/` 전체(하위 폴더 포함, `_` 시작 파일 제외)를 `2_두뇌/index.md`의 "원본 반영 대장"과 대조해 찾는다:
① 대장에 없는 새 파일 ② 수정시각이 대장 기록과 달라진 파일 ③ 대장에 있지만 파싱본이 없는 파일.

### 2. 형식별 변환 (도구: `9_형식/`)

| 원본 형식 | 방법 |
|---|---|
| `.md` | 그대로 복사 |
| `.txt` | 복사 후 파일명 뒤에 `.md`를 덧붙임 |
| `.hwp`(3.x/5.x) · `.hwpx` · `.pdf` · `.docx` · 구형 `.xls` | kordoc으로 Markdown 추출 (`npx -y kordoc@^3`, 사용법: `9_형식/references/kordoc.md`) |
| `.xlsx` | openpyxl로 시트 → Markdown 표 (`9_형식/references/workflows/xlsx-forms.md`) |
| 암호·DRM `.hwp` | COM 폴백(`9_형식/scripts/convert_hwp.py`)으로 HWPX 변환 후 kordoc |
| 구형 `.doc` | 미지원 — 사용자에게 `.docx` 재저장을 요청한다 |

kordoc은 **한 파일씩 실행하고 출력명을 직접 지정**한다: `npx -y kordoc@^3 <원본> -o <파싱본 경로>`.
일괄 모드(`-d`)는 쓰지 않는다 — 출력명이 확장자를 뗀 `수업안.md`식이라 아래 명명 규칙과 어긋나고,
`수업안.hwp`·`수업안.pdf`가 공존하면 서로 덮어쓴다.

### 3. 저장 규칙
- 위치: `1_파싱/` 아래, `0_원본/`과 같은 상대 경로.
- 파일명: 원본이 `.md`면 같은 이름, 그 외에는 **원본 파일명 그대로 + `.md`** (예: `수업안.hwp` → `수업안.hwp.md`) — 어떤 원본에서 왔는지 이름만으로 보이게.
- 이미지: kordoc이 파싱본 옆 `images/`에 `image_001.png`식으로 저장하는데, 번호가 문서마다 1부터라 그대로 두면 다음 문서가 덮어쓴다. **각 파일 파싱 직후, 다음 파일로 넘어가기 전에**: ① `images/` → `<원본 파일명>.images/`로 개명 (예: `수업안.hwp.images/`) ② 파싱본 안의 `](image_` 링크를 `](<원본 파일명>.images/image_`로 치환 (kordoc은 `-o` 모드에서 링크에 폴더 접두사를 안 붙인다). base64 인라인(`--inline-images`)은 md가 비대해져 증류 입력에 부적합 — 쓰지 않는다.
- 파일 맨 위 frontmatter:

  ```yaml
  ---
  원본: 0_원본/<상대경로>
  원본-수정시각: <mtime>
  파싱일: <YYYY-MM-DD>
  도구: kordoc | 복사 | openpyxl | COM+kordoc
  ---
  ```

### 4. 검수 안내 (증류 전 확인 지점)
표·서식이 많은 hwp/pdf는 변환 손실이 날 수 있다. 변환을 마치면 사용자에게 알린다:
"`1_파싱/`의 변환본을 열어 내용이 온전한지 훑어보세요 (특히 표와 이미지 링크). 이상 없으면 '증류해줘'라고 하면 됩니다."

### 5. 대장 갱신
`2_두뇌/index.md` 원본 반영 대장에 파싱본 경로·파싱일을 기록한다. 반영처는 증류 전이므로 비워 둔다.

## 예외 상황

- **파싱 실패** (깨진 파일, 미지원 형식) → 대장 파싱본 칸에 "실패: 사유"로 기록하고 사용자에게 알린다.
- **원본이 삭제된 파싱본 발견** → 사용자에게 알리고, 동의받아 파싱본과 대장 항목을 정리한다 (딸린 `<원본 파일명>.images/` 폴더 포함).
- **이미 반영처가 있는데 파싱본만 없는 항목** (v1 마이그레이션 직후) → 파싱본만 만들어 대장을 채운다. 재증류하지 않는다.
