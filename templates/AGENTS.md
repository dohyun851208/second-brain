## 세션 시작 시 1회 점검
`0_원본/`의 파일 목록·수정시각을 `2_두뇌/index.md`의 "원본 반영 대장"과 대조한다 (`_`로 시작하는 파일은 시스템 안내문 — 제외).
- 대장에 없거나 수정된 원본 발견 → 알리고, 동의받아 `8_시스템/파서-프롬프트.md`로 파싱한다.
- 파싱본만 있고 반영처가 빈 항목 발견 → 증류를 제안한다 (`8_시스템/컴파일러-프롬프트.md`).
- `5_규범자료/`·`6_참고자료/`에 파싱본 없는 파일 발견 → **파싱만** 제안한다. 증류 대상이 아니므로 증류는 제안하지 않는다.
- `7_개인정보이미지/`는 이 점검에서 완전히 제외한다.
몰래 두뇌를 바꾸지 않는다 — 파싱·증류 모두 사용자 승인 후 실행.

## 층위
- `0_원본/`: 불변 원본 (hwp·hwpx·pdf·docx·xls·xlsx·png·jpg·webp·md·txt 아무 형식). 직접 읽지 않는다 — 파싱과 원본 대조 시에만
- `1_파싱/`: 원본 전체의 md 변환본. 드릴다운·증류의 입력. 평소엔 읽지 않는다
- `2_두뇌/`: 판단 기준. `index.md`를 먼저 읽고 필요한 모듈만 연다
- `5_규범자료/`: 성취기준·지침·법령처럼 **한 글자도 바꿀 수 없는** 남의 자료. 파싱 O, **증류 X, 요약 X**. 파싱본은 이 폴더 안에 둔다
- `6_참고자료/`: 교재·남의 수업안처럼 **재구성해도 되는** 남의 자료. 파싱 O, **증류 X**. 파싱본은 이 폴더 안에 둔다
- `7_개인정보이미지/`: 서명·도장·신분증·통장사본·증명사진처럼 원형 그대로 재사용할 이미지. 컴파일·OCR 금지
- `8_시스템/`: 두뇌 제작·갱신 시에만
- `9_형식/`: hwpx·xlsx 등 산출 형식 능력 + 파싱 엔진(kordoc). 해당 작업 시에만

## 라우팅

우선순위: **`5_규범자료`(넘을 수 없는 선) > `2_두뇌`(그 안에서의 선택) > `7_개인정보이미지` > `6_참고자료`(재료)**.

- `2_두뇌/index.md`를 읽고, 담당 영역이 작업과 맞는 모듈만 연다. `판단기준-공통.md`는 항상 읽는다.
- 개인 사실 정보(경력·자격 등)가 필요하면 `팩트카드.md`.
- 남이 만든 자료가 필요하면 `5_규범자료/자료목록.md` 또는 `6_참고자료/자료목록.md`를 먼저 읽고 필요한 항목만 연다. 목록 없이 폴더를 훑지 않는다.
- 내가 쓴 장문(책·수업안 등)의 **원문**을 인용해야 하면 `2_두뇌/index.md` 대장에서 해당 원본을 찾아 `1_파싱/`의 파싱본을 연다.
- 개인화가 무의미한 요청(단순 사실 질문 등) → 두뇌 생략.
- hwp/hwpx/xls/xlsx 산출·편집, pdf·docx 표 추출·정밀 파싱, 스캔 PDF·이미지 OCR, 행정문서(공문·회의록·공적조서 등) → 두뇌 모듈 + `9_형식/라우팅.md`. 볼트 밖 절대경로 파일도 동일하게 처리하고, 산출물은 원본 옆에 저장한다.
  - HWP/HWPX 일반 작업은 Kordoc `@^4` 단일 경로다. 지원되는 암호 문서는 `--password`로 열되 암호를 응답·로그에 남기지 않는다. 직접 XML·COM·다른 생성기로 우회하지 않는다.
  - 새 HWPX의 마크다운 이미지는 Kordoc `generate --image-dir`로 임베드한다. Kordoc이 지원하지 않는 **기존 문서의 지정 위치 래스터 이미지 쓰기**만 승인 이미지 예외로 `place_image.py` 실측 경로를 쓴다. 서명·도장·신분증·통장사본·증명사진·일반 사진을 모두 지원한다. `.hwpx`는 바로 처리하고, `.hwp`는 한컴 COM으로 임시 HWPX를 한 번 만든 뒤 처리한다. 최종본은 HWPX로만 내며 원본 HWP는 보존한다. `place_signature.py`는 기존 명령 호환용이고 내부 모듈은 직접 실행하지 않는다. 실행 조건 미충족·변환 실패 시 다른 경로로 우회하지 않는다.
  - 이미지 경로의 트리거는 최초 요청 문구가 아니라 최종 제출 요건과 승인 상태다. 양식 점검이나 작업 중 필수 이미지·서명·날인란을 발견하면 승인 상태를 확인하고, 승인되면 위 경로를 실행한다. 개인정보 자산이 미승인이라면 사용할 자산과 용도를 한 번 확인하며, 필수란을 말없이 비운 채 완성본으로 보고하지 않는다. 사용자가 특정 문서와 일반 이미지 삽입을 직접 요청했다면 그 범위는 승인된 것으로 본다.
- 특정 양식 작성·제출서류 완성 요청 → 대상 양식 + 관련 `2_두뇌/` 모듈 + `5_규범자료/자료목록.md`(양식에 규범 항목이 있을 때) + `7_개인정보이미지/자산목록.md` + `9_형식/라우팅.md`를 결합한다. 자산 파일은 목록에서 필요한 후보를 고른 뒤 `7_개인정보이미지/_안내.md`의 승인 규칙에 따라 필요한 것만 연다.

## 남의 자료 (5·6층)

- **판별**: 내가 만든 것 → `0_원본/`(증류함). 남이 만든 것 → 내 말로 바꾸면 틀린 게 되면 `5_규범자료/`, 재구성해도 되면 `6_참고자료/`. 5·6층은 어떤 경우에도 증류하지 않는다.
- **규범 인용은 없으면 안 쓴다**: 성취기준 코드·법령 조항·지침 문장의 직접 인용이 필요하면 `5_규범자료/자료목록.md`에서 해당 **범위**가 있는지 먼저 확인한다. 없으면 지어내지 말고 사용자에게 묻는다(넣어줄지, 그 칸을 비울지). 일반 서술·활동 설계에는 이 문을 걸지 않는다 — 대조하면 맞다/틀리다가 나오는 값에만 적용한다. 인용은 `현행` 상태에서만 하고 `_지난판/`은 과거 문서 검증 요청 때만 연다.
- **출처 표시**: 5층 인용에는 출처를 붙여 원문 대조가 가능함을 보이고, 6층을 반영한 부분에는 출처와 함께 **"두뇌 규칙 근거 없음"**을 밝힌다. 두뇌 규칙은 짧고 참고자료 원문은 길어서, 표시가 없으면 양이 많은 쪽이 판단을 밀어내고도 티가 나지 않는다.
- 5·6층은 민감정보가 아니므로 열람 승인이 필요 없다 (`7_개인정보이미지/`와 다른 점).

## 개인정보 이미지
- **읽어서 지식화할 이미지**는 `0_원본/`, **형태 그대로 재사용할 개인정보 이미지**는 `7_개인정보이미지/`다. 일회성 비민감 일반 사진은 사용자가 지정한 경로에서 바로 쓰고 개인정보 자산 목록에 등록하지 않는다.
- `7_개인정보이미지/`는 세션 원본 점검·파싱·증류·두뇌 반영에서 항상 제외한다. 주민번호·계좌번호·서명 이미지의 OCR 결과를 `1_파싱/`·`2_두뇌/`·로그에 남기지 않는다.
- 일반적인 양식 작성 요청에서는 쓰기 전에 필수·선택 항목과 이미지 칸·별도 첨부·서명·날인란을 전체 점검하고 사용할 자산 후보를 제시한다. 필수 개인정보 이미지·서명·날인을 발견했지만 승인이 없으면 사용할 자산과 용도를 한 번 확인하고, 승인 뒤 같은 작업을 계속한다. 선택·모호한 이미지란은 자동 삽입하지 않는다. 사용자가 특정 문서와 자산의 삽입을 명시했다면 그 범위는 승인된 것으로 본다. 별도 파일 첨부 요구를 문서 안 삽입으로 바꾸지 않는다.
- 원본 이미지는 불변이다. 편집은 작업용 사본이나 최종 문서 내부에서만 하고, 완료 후 `7_개인정보이미지/사용기록.md`에 민감 값 없이 기록한다.

## 대리 판단
1. 선택지가 있으면 하나를 고른다. 근거 규칙 번호와 함께 왜 {{이름}}다운지 설명한다.
2. 장점보다 {{이름}}이(가) 수정 요구할 가능성이 높은 부분을 먼저 본다.
3. 규칙으로 부족하면 추측하지 말고 "확인 필요"로 표시한다. 규범 값(성취기준 코드·조항·지침 인용문)은 `5_규범자료/`에 없으면 이 원칙이 그대로 적용된다 — 그럴듯하게 지어내지 않는다.
4. 검수·선택 응답 형식: ①선택 ②왜 {{이름}}다운가 ③수정 예상 지점 ④수정안 ⑤확인 필요
   ②를 규칙으로 채우지 못하고 `6_참고자료/`에서 끌어온 부분이 있으면 그 자리에 출처와 "두뇌 규칙 근거 없음"을 남긴다.

## 드릴다운
규칙끼리 충돌 / 확신도 낮은 규칙이 결정에 핵심 / 뉘앙스가 중요 → 출처 링크를 따라 `1_파싱/`의 파싱본을 읽는다.
출처가 `0_원본/`을 가리키거나(구버전 규칙) 표·서식 손실이 의심되면 `9_형식/` 도구로 원본을 직접 연다.

## 유지보수
- "나답지 않다" 피드백 → 해당 규칙 수정 + `8_시스템/log.md` 기록. 감사·버전은 `8_시스템/갱신절차.md`.
- "세컨드브레인 상태/업그레이드" → 시스템 버전과 함께 kordoc 실행 버전·호환 메이저도 `8_시스템/갱신절차.md`에 따라 점검한다.
- 세션 원본 후보 제안(수동, 매 턴 아님): 세션을 마칠 때 또는 "이 대화 저장할 만해?"라고 물으면 — 그 세션에 숙고의 흔적(반박·이유 제시·선택지 중 의식적 선택)이 있었는지 보고, 있으면 `0_원본/` 저장 후보로 **제안만** 한다. 실시간 대화를 두뇌에 직접 쓰지 않는다. 저장은 사용자가 정하고, 저장하면 다음 파싱·증류에서 앞문으로 반영된다. 단순 승인("응 좋아")은 숙고 흔적이 아니다 — 후보로 올리지 않는다.
  - **6층 자료를 쓴 세션은 후보 신호다**: `6_참고자료/`의 자료 중 무엇을 채택하고 무엇을 왜 버렸는지가 드러난 세션은 숙고 흔적으로 본다. 그 판단은 자료가 아니라 사용자의 것이므로 `0_원본/`에 속하며, 저장하면 다음 증류에서 규칙이 된다. 남의 자료가 두뇌를 묻지 않고 키우는 경로가 이것뿐이다.
- 지휘자 본문은 이 파일에만 쓴다. `CLAUDE.md`는 `@AGENTS.md` 한 줄 유지.
