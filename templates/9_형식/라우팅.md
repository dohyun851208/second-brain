# 형식 라우팅

HWP/HWPX·XLS/XLSX 산출·편집과 교사 행정문서 작업의 진입점.

## 우선순위

1. **`5_규범자료/`의 규범** — 성취기준·지침·법령. 없으면 지어내지 않고 묻는다.
2. **`2_두뇌/`의 개인 규칙** — 규범 안에서 사용자의 선택을 반영한다.
3. **`7_개인정보이미지/`의 승인된 자산** — 양식이 요구하는 이미지·첨부만 사용한다.
4. **`6_참고자료/`의 재료** — 개인 규칙과 부딪치면 개인 규칙이 우선이다. 반영하면 출처를 표시한다.
5. **내용 규칙** (`references/content-rules/`)과 **형식 워크플로** (`references/workflows/`).

## 양식 + 규범·자산 결합

1. 쓰기 전에 대상 양식 전체를 사전점검해 필수·선택 텍스트, 이미지 칸, 별도 첨부, 서명·날인 위치를 확인한다.
2. 성취기준 코드·법령 조항·지침 직접 인용이 필요하면 `5_규범자료/자료목록.md`에서 해당 범위를 확인한다. 없으면 그 칸을 비우고 사용자에게 묻는다.
3. 일반 내용은 `2_두뇌/팩트카드.md`와 관련 모듈에서 채운다. `6_참고자료/`를 사용한 부분에는 출처와 "두뇌 규칙 근거 없음"을 표시한다.
4. `7_개인정보이미지/자산목록.md`에서 필요한 후보만 고르고 `_안내.md`의 승인 범위를 확인한다. 필수 개인정보 이미지·서명·날인을 발견했지만 미승인이라면 사용할 자산과 용도를 한 번 확인하고, 승인 뒤 같은 작업을 계속한다.
5. 원본 양식과 원본 이미지는 덮어쓰지 않는다. 결과는 원본 옆의 새 파일로 만든다.
6. 주요 값·이미지 종류·첨부 수·서명 위치를 확인하고, 성공한 개인정보 이미지 사용만 `사용기록.md`에 민감 값 없이 기록한다.

**이미지 경로의 실행 조건은 최초 요청에 서명·이미지라는 단어가 있었는지가 아니라 최종 제출본에 이미지가 필요한가와 사용 범위가 승인됐는가다.** 작업 중 필수 신분증·통장사본·증명사진·서명·날인란을 뒤늦게 발견해도 이미지 단계로 라우팅한다. 선택·모호한 이미지란은 자동 삽입하지 않고 확인하며, 필수란을 말없이 비운 채 완성본으로 보고하지 않는다.

## HWP/HWPX — Kordoc 단일 경로

실행 정본은 `npx -y kordoc@^4`이며 마지막 검증판은 4.9.2다. 자세한 명령은 `references/kordoc.md`를 따른다.

| 작업 | 경로 |
|---|---|
| 읽기·Markdown 파싱 | Kordoc parse |
| 기존 내용 수정 | Kordoc `patch` — 원본 포맷 유지 |
| HWPX 양식 채우기 | Kordoc `fill --dry-run` 후 `fill` |
| 새 HWPX 생성 | Kordoc `generate`; 마크다운 이미지는 `--image-dir`로 임베드 |
| 비교·검수 | Kordoc 파싱 결과 비교·Markdown `lint`(`--munche` 필요 여부 판별)·`validate` |
| 미리보기 | 필요할 때 Kordoc `render` |

- `.hwp`의 단순 내용 수정은 `patch`로 처리한다. HWPX preserve가 필요한 `fill`을 `.hwp`에 직행시키지 않는다.
- 지원되는 HWPX·HWP3·HWP5 암호 문서는 `--password`로 열고 암호를 응답·로그에 남기지 않는다. 한컴 DRM·손상 파일·지원하지 않는 구조처럼 Kordoc이 안전하게 처리하지 못하는 입력은 **그대로 둔다**. 아래 승인 이미지 배치 예외가 아니면 COM 변환, 직접 XML 편집, pack/unpack, 다른 생성기로 자동 우회하지 않는다.
- 일반 작업에서 `references/hwpx/`, HWPX 골격 `templates/`, 저수준 XML 스크립트를 열거나 호출하지 않는다. 이전 볼트에 남아 있어도 삭제하지 않고 무시한다.
- 세부 순서는 `references/workflows/hwpx-forms.md`를 따른다.

## 기존 문서의 승인 이미지 지정 위치 배치 — 유일한 예외

새 HWPX 생성 중 마크다운 이미지는 Kordoc `generate --image-dir`로 넣는다. Kordoc은 일반 래스터 이미지를 기존 HWP/HWPX의 지정 위치에 쓰는 경로를 제공하지 않으며, `seal`도 Second Brain의 서명·도장 정본이 아니다. 이 기존 문서 작업에서 승인된 서명·도장·신분증·통장사본·증명사진·일반 사진은 `scripts/place_image.py`만 사용한다.
이 스크립트는 `.hwp` 입력이면 한컴 COM으로 임시 HWPX를 한 번 만든 뒤, PNG/JPG/JPEG/BMP 원본의 비율을 유지하고 한컴 렌더 결과를 실측해 위치를 보정한 다음 오차를 검증한다. `place_signature.py`는 기존 명령 호환용이다.
내부 변환·삽입 모듈인 `hwp_to_hwpx.py`·`insert_signature_hwpx.py`를 직접 실행하거나 XML을 즉석 편집하지 않는다.

조건:

- 입력은 `.hwp` 또는 `.hwpx`, 이미지는 `.png`·`.jpg`·`.jpeg`·`.bmp`다. `.hwp`의 COM 변환은 **승인된 이미지 배치 작업 안에서만** 허용하며 일반 HWP 작업의 우회 경로로 쓰지 않는다.
- 사용자가 특정 문서와 이미지를 직접 지정했다면 그 범위는 승인된 것으로 본다. 양식 점검 중 필수 개인정보 이미지란을 발견했지만 미승인이라면 자산과 용도를 한 번 확인한다. 현재 작업본이 `.hwp`이면 승인 뒤 임시 HWPX 변환부터 이어서 수행한다.
- Windows 한컴, Python `pywin32`, PyMuPDF가 필요하다. 조건이 없으면 서명은 Kordoc `seal`로, 일반 이미지는 임의 도구로 우회하지 않고 원본을 그대로 둔다.
- 사용자 승인 규칙은 `7_개인정보이미지/_안내.md`를 따른다.
- 텍스트 값은 먼저 Kordoc으로 채우고, 이미지는 마지막에 배치한다. 양식이 별도 파일 첨부를 요구하면 문서 안 삽입으로 대체하지 않는다.
- 원본은 덮어쓰지 않는다. `.hwp` 입력도 최종본은 `*_완성본.hwpx`이며, 최종 HWPX를 COM으로 다시 저장하거나 HWP로 되돌리지 않는다.

```powershell
# 1. 양식의 표기·기존 그림 위치와 쪽 좌표를 mm로 확인
py -3 scripts/place_image.py "신청서.hwpx" "통장사본.jpg" `
  --report --find "통장사본" --find "(서명)"

# 2-a. 서명·도장: 이름 끝에서 시작하도록 배치
py -3 scripts/place_image.py "신청서.hwpx" "서명.png" `
  --output "신청서_완성본.hwpx" `
  --anchor-para "신청인은 위 내용에 동의합니다" `
  --after-text "홍길동" --width-mm 24

# 2-b. 신분증·통장사본·증명사진·일반 사진: 조사한 좌·상단에 배치
py -3 scripts/place_image.py "신청서.hwpx" "통장사본.jpg" `
  --output "신청서_완성본.hwpx" `
  --anchor-para "첨부 이미지" `
  --target-left-mm 25 --target-top-mm 120 --width-mm 80

# HWP 입력도 같은 명령을 사용하며 출력은 HWPX
py -3 scripts/place_image.py "신청서.hwp" "증명사진.jpg" `
  --output "신청서_완성본.hwpx" `
  --anchor-para "사진" `
  --target-left-mm 150 --target-top-mm 25 --width-mm 30
```

`--after-text`는 글자 옆 서명·도장에만 쓴다. 일반 이미지는 `--report`와 렌더를 확인한 뒤 `--target-left-mm` + `--target-top-mm`(또는 `--target-bottom-mm`)으로 명시 배치한다. `--anchor-para`는 목표보다 위에 있는 고유 문단을 고른다. 여러 이미지는 앞 단계 출력을 다음 단계 입력으로 순차 처리하고 각 단계를 검증한다. HWP 변환본·중간본·렌더 파일은 성공·실패와 관계없이 정리한다. 출력이 이미 있으면 덮어쓰지 않으며, 명시적인 `--overwrite`가 있을 때만 교체한다.

## 저장·검증

- 원본은 덮어쓰지 않는다. 결과는 원본 옆에 `_완성본`, `_제출용`, `_검토본` 접미사로 저장하고 이름 충돌 시 번호를 붙인다.
- 새 공문 원고는 `lint`(보고서·계획서는 `--munche`) 뒤 생성하고, 일반 HWP/HWPX 결과는 Kordoc `validate`와 핵심 값 확인으로 검증한다. `lint`에는 문서 바이너리가 아니라 md/txt만 입력한다.
- 이미지 삽입 결과는 `place_image.py`의 구조 검사와 한컴 렌더 실측을 정본으로 삼는다. 원본 비율·목표 위치·페이지 경계를 확인하고 임시 PDF는 자동 삭제한다.
- 실패한 작업은 성공처럼 보고하지 않는다. 원본과 기존 출력은 그대로 두고 실패 단계와 이유만 알린다.
