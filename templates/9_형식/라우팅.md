# 형식 라우팅

HWP/HWPX·XLS/XLSX 산출·편집과 교사 행정문서 작업의 진입점.

## 우선순위

1. **`5_규범자료/`의 규범** — 성취기준·지침·법령. 없으면 지어내지 않고 묻는다.
2. **`2_두뇌/`의 개인 규칙** — 규범 안에서 사용자의 선택을 반영한다.
3. **`7_개인정보이미지/`의 승인된 자산** — 양식이 요구하는 이미지·첨부만 사용한다.
4. **`6_참고자료/`의 재료** — 개인 규칙과 부딪치면 개인 규칙이 우선이다. 반영하면 출처를 표시한다.
5. **내용 규칙** (`references/content-rules/`)과 **형식 워크플로** (`references/workflows/`).

## 양식 + 규범·자산 결합

1. 대상 양식의 필수 텍스트, 이미지 칸, 첨부, 서명·날인 위치를 먼저 확인한다.
2. 성취기준 코드·법령 조항·지침 직접 인용이 필요하면 `5_규범자료/자료목록.md`에서 해당 범위를 확인한다. 없으면 그 칸을 비우고 사용자에게 묻는다.
3. 일반 내용은 `2_두뇌/팩트카드.md`와 관련 모듈에서 채운다. `6_참고자료/`를 사용한 부분에는 출처와 "두뇌 규칙 근거 없음"을 표시한다.
4. `7_개인정보이미지/자산목록.md`에서 필요한 후보만 고르고 `_안내.md`의 승인 범위를 확인한다.
5. 원본 양식과 원본 이미지는 덮어쓰지 않는다. 결과는 원본 옆의 새 파일로 만든다.
6. 주요 값·이미지 종류·첨부 수·서명 위치를 확인하고, 성공한 개인정보 이미지 사용만 `사용기록.md`에 민감 값 없이 기록한다.

## HWP/HWPX — Kordoc 단일 경로

실행 정본은 `npx -y kordoc@^4`이며 자세한 명령은 `references/kordoc.md`를 따른다.

| 작업 | 경로 |
|---|---|
| 읽기·Markdown 파싱 | Kordoc parse |
| 기존 내용 수정 | Kordoc `patch` — 원본 포맷 유지 |
| HWPX 양식 채우기 | Kordoc `fill --dry-run` 후 `fill` |
| 새 HWPX 생성 | Kordoc `generate` |
| 비교·검수 | Kordoc 파싱 결과 비교·`lint`·`validate` |
| 미리보기 | 필요할 때 Kordoc `render` |

- `.hwp`의 단순 내용 수정은 `patch`로 처리한다. HWPX preserve가 필요한 `fill`을 `.hwp`에 직행시키지 않는다.
- Kordoc이 안전하게 처리하지 못하는 암호·DRM 문서, 손상 파일, 지원하지 않는 구조는 **그대로 둔다**. COM 변환, 직접 XML 편집, pack/unpack, 다른 생성기로 자동 우회하지 않는다.
- 일반 작업에서 `references/hwpx/`, HWPX 골격 `templates/`, 저수준 XML 스크립트를 열거나 호출하지 않는다. 이전 볼트에 남아 있어도 삭제하지 않고 무시한다.
- 세부 순서는 `references/workflows/hwpx-forms.md`를 따른다.

## 서명·도장 HWPX 배치 — 유일한 예외

Kordoc `seal`은 Second Brain의 서명·도장 정본이 아니다. 승인된 개인정보 이미지의 배치는 `scripts/place_signature.py`만 사용한다.
이 스크립트는 원본 비율을 유지하고, 한컴 렌더 결과를 실측해 위치를 보정한 뒤 오차를 검증한다.
내부 삽입 모듈인 `insert_signature_hwpx.py`를 직접 실행하거나 XML을 즉석 편집하지 않는다.

조건:

- 입력 문서는 `.hwpx`여야 한다. `.hwp`면 자동 변환하지 말고 HWPX 제공이 필요하다고 알린다.
- Windows 한컴, Python `pywin32`, PyMuPDF가 필요하다. 조건이 없으면 Kordoc `seal`로 우회하지 않고 원본을 그대로 둔다.
- 사용자 승인 규칙은 `7_개인정보이미지/_안내.md`를 따른다.
- 텍스트 값은 먼저 Kordoc으로 채우고, 서명은 마지막에 배치한다.

```powershell
# 1. 양식의 이름·서명 표기·기존 그림 위치를 mm로 확인
py -3 scripts/place_signature.py "신청서.hwpx" "서명.png" `
  --report --find "홍길동" --find "(서명)"

# 2. 이름 끝에서 시작하도록 배치
py -3 scripts/place_signature.py "신청서.hwpx" "서명.png" `
  --output "신청서_완성본.hwpx" `
  --anchor-para "신청인은 위 내용에 동의합니다" `
  --after-text "홍길동" --width-mm 24
```

`--anchor-para`는 목표 줄보다 위에 있는 고유 문단을 고른다. 출력이 이미 있으면 덮어쓰지 않으며, 명시적인 `--overwrite`가 있을 때만 교체한다.

## XLS/XLSX

- 읽기 전용은 Kordoc을 사용할 수 있다.
- 산출·편집은 `references/workflows/xlsx-forms.md`를 따른다. 병합 범위는 좌상단 셀에만 쓰고 저장 후 다시 열어 검증한다.

## 저장·검증

- 원본은 덮어쓰지 않는다. 결과는 원본 옆에 `_완성본`, `_제출용`, `_검토본` 접미사로 저장하고 이름 충돌 시 번호를 붙인다.
- 일반 HWP/HWPX 결과는 Kordoc `validate`와 핵심 값 확인으로 검증한다.
- 서명·도장 결과는 `place_signature.py`의 구조 검사와 한컴 렌더 실측을 정본으로 삼는다. 임시 PDF는 자동 삭제한다.
- 실패한 작업은 성공처럼 보고하지 않는다. 원본과 기존 출력은 그대로 두고 실패 단계와 이유만 알린다.
