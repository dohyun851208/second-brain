# 형식 라우팅

hwp/hwpx/xls/xlsx 산출·편집과 교사 행정문서 작업의 진입점. (기반: [teacher 스킬](https://github.com/dohyun851208/teacher), HTML 슬라이드 제외)

## 우선순위

1. **`5_규범자료/`의 규범** (성취기준·지침·법령) — 넘을 수 없는 선. **없으면 지어내지 않고 묻는다**
2. **`2_두뇌/`의 개인 규칙** (글쓰기·팩트카드 등) — 그 선 안에서의 선택
3. **`7_개인정보이미지/`의 승인된 자산** — 양식이 요구하는 이미지·첨부만
4. **`6_참고자료/`의 재료** — 내 규칙과 부딪치면 내 규칙이 이긴다. 반영하면 출처 표시 의무
5. **내용 규칙** (`references/content-rules/`) — 문서 종류별 일반 관례
6. **형식 워크플로** (`references/workflows/`) — 파일 구조 보존·검증 절차

## 양식 + 규범·자산 결합

특정 양식 작성 요청에서는 다음 순서를 지킨다.

1. 대상 양식의 필수 텍스트 항목, 이미지 칸, 첨부 요구, 서명·날인 위치를 먼저 분석한다.
   이때 **규범 항목**(성취기준 코드, 법령·규정 조항, 지침 문장의 직접 인용)이 있는지 함께 표시한다.
2. 규범 항목이 있으면 `5_규범자료/자료목록.md`에서 **해당 범위**가 있는지 확인한다.
   - 있으면 파싱본에서 원문 그대로 인용하고 출처를 붙인다: `[6국03-02]` (2022 개정 국어과, 3~4학년군)
   - **없으면 지어내지 않는다.** 값을 비운 채 사용자에게 묻는다 — 자료를 넣어줄지, 그 칸만 비우고 나머지를 채울지.
     "국어과 성취기준은 있는데 5~6학년군이 없다"도 없는 것이다. 범위 단위로 판단한다.
   - 이 문은 대조하면 맞다/틀리다가 나오는 값에만 건다. 활동 설계·평가 방법 같은 일반 서술에는 걸지 않는다.
3. 일반 내용은 `2_두뇌/팩트카드.md`와 관련 모듈에서 채운다. 모르는 값은 추측하지 않고 한 번에 묻는다.
   `6_참고자료/`를 재료로 썼으면 해당 부분에 출처와 "두뇌 규칙 근거 없음"을 표시한다.
4. `7_개인정보이미지/자산목록.md`에서 양식에 필요한 후보만 고른다. 폴더 전체를 열거나 일괄 OCR하지 않는다.
5. `7_개인정보이미지/_안내.md`에 따라 민감 이미지의 열람·값 전사·삽입 승인을 확인한다. 사용자가 특정 문서와 자산을 명시한 요청은 그 범위의 승인이다.
6. 원본 이미지와 원본 양식은 덮어쓰지 않는다. 크기·자르기·투명도 조정은 작업용 사본 또는 산출물 내부에서만 한다.
7. 텍스트 값, 이미지 종류, 첨부 수, 서명 위치를 검증하고 성공한 사용을 `7_개인정보이미지/사용기록.md`에 기록한다. 규범 항목은 원문과 글자 단위로 대조한다.

## 형식 워크플로

- **kordoc 엔진** (`npx -y kordoc@^4`, 사용법: `references/kordoc.md`) — 읽기·패치·비교·날인 담당:
  - 문서 읽기: `.hwp`(3.x/5.x)·`.hwpx`·`.pdf`·`.docx`·구형 `.xls` → Markdown. 스캔 PDF는 `--ocr`, `.png`·`.jpg`·`.webp`는 직접 입력해 로컬 OCR. 한컴 COM 불필요, 암호·DRM 문서만 COM 폴백(`scripts/convert_hwp.py`)
  - 일괄 파싱은 `8_시스템/파서-프롬프트.md`가 정본 — 이 읽기 엔진을 그대로 쓴다. 출력 위치는 출신에 따라 다르다: `0_원본/`→`1_파싱/`, `5_규범자료/`·`6_참고자료/`→**원본 옆 같은 폴더**
  - 기존 문서의 내용 수정: `patch` — **원본 포맷 유지** (`.hwp`→`.hwp` 바이너리 패치, `.hwpx`→`.hwpx`, 변환 없음). 직접 XML 편집은 구조 변경(표 추가·양식 재설계)이 필요할 때만
  - 문서 비교(신구대조·검수), 도장/서명 배치(`seal`, HWPX 전용)
- `.hwp` / `.hwpx` 산출 — **원본 포맷 유지가 기본**. `.hwpx` 변환은 preserve 채우기·XML 편집이 필요한 작업에만:
  - 서식 채우기·구조 편집 → `references/workflows/hwpx-forms.md` (정본 절차). `.hwp`는 COM 임시 변환 1회 후 HWPX 편집, 최종 `.hwpx` (완성본을 `.hwp`로 COM 재저장하지 않는다)
  - **`.hwp`에 `kordoc fill` 직행 금지**: preserve 모드가 HWPX 전용이라 `.hwp`는 파싱→재구성 경로로 빠져 표가 깨진다 (실측 확인 2026-07). fill은 `.hwpx`에만, `.hwp` 채우기는 COM 변환 후
  - 분석 먼저: `scripts/clone_form.py --analyze` 또는 `kordoc fill --dry-run`(라벨 목록), 값 확인은 `Contents/section0.xml` 직접 검사
  - 새 문서 생성은 볼트 `templates/` 우선 (사용자 스타일 반영). 템플릿 없는 유형이나 차트·수식 필요 시 `kordoc generate` 폴백
  - generate로 학교 양식의 표 서식(괘선·음영·열폭)까지 재현해야 하면 **서식 프로필** (`references/kordoc.md`의 해당 절) — 양식에서 서식만 JSON으로 추출해 `templates/`에 보관·재사용 (개인정보 무포함)
  - 기존 양식 채우기에 `md2hwpx.py`를 폴백으로 쓰지 않는다 (표 구조가 깨짐 — 사용자가 재설계에 동의한 경우만)
- `.xls` / `.xlsx` 산출 → `references/workflows/xlsx-forms.md` (openpyxl, 병합 범위는 좌상단 셀에만 쓰기, 저장 후 재열어 검증). 읽기 전용이면 kordoc이 구형 `.xls`까지 처리
- 저수준 도구: `scripts/` (분석·치환·생성·검증·서명삽입·pack/unpack), `templates/` (공문·회의록·계획서·보고서·government·base 골격), `references/hwpx/` (XML 구조·공문서 스타일 지식)
- 발표자료·슬라이드는 형식층 담당이 아니다 (일반 능력으로 처리)

## 내용 규칙 매핑 (색인: `references/teacher-admin-rules.md`)

- 이력서·경력기술서 → `references/content-rules/resume.md`
- 공적조서·표창 추천서 → `references/content-rules/achievement-statement.md`
- 신청서·지원서 → `references/content-rules/application.md`
- 회의록·협의록 → `references/content-rules/meeting-minutes.md`
- 예산요구서·예산표 → `references/content-rules/budget-request.md`
- 그 외 공문·보고서·계획서 → `references/content-rules/common.md`

## 저장 규칙

- 원본은 절대 덮어쓰지 않는다. 결과물은 원본 파일 옆에 `_완성본`, `_제출용`, `_검토본` 접미사로 저장 (중복 시 `_완성본2`, `_완성본3`)
- 원본 없는 새 문서는 사용자가 지정한 위치에 저장. 별도 `완성본/` 폴더는 요청 시에만
- 완성된 산출물 중 판례 가치가 있는 것은 `0_원본/`에 복사해두라고 제안할 수 있다

## 인코딩·검증

- 텍스트 파일은 UTF-8로 저장. Python은 항상 `encoding="utf-8"`
- 한글 경로를 다루는 PowerShell 세션은 먼저: `chcp 65001` + `[Console]::OutputEncoding = [System.Text.Encoding]::UTF8`
- HWPX 검증은 구조 검증 + 핵심 값 확인이 기본: `scripts/verify_hwpx.py` + `kordoc validate` 이중 확인 (한컴독스 업로드 거부 요인 차단). PDF/이미지 렌더링이나 불필요한 검증 사본을 만들지 않는다 (미리보기는 사용자 요청 시 `kordoc render`만)
