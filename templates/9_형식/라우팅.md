# 형식 라우팅

HWP/HWPX·XLS/XLSX 산출·편집과 교사 행정문서 작업의 진입점.

> 이 파일은 **시스템 파일**이라 업그레이드 때 새 판으로 교체된다. 작업 중 알게 된 이 볼트만의 요령은 여기가 아니라 `9_형식/현장메모.md`에 적고, 작업 전에 그 파일도 함께 읽는다.

## 우선순위

1. **`5_규범자료/`의 규범** — 성취기준·지침·법령. 없으면 지어내지 않고 묻는다.
2. **`2_두뇌/`의 개인 규칙** — 규범 안에서 사용자의 선택을 반영한다.
3. **`7_개인정보이미지/`의 승인된 자산** — 양식이 요구하는 이미지·첨부만 사용한다.
4. **`6_참고자료/`의 재료** — 개인 규칙과 부딪치면 개인 규칙이 우선이다. 반영하면 출처를 표시한다.
5. **내용 규칙** (`9_형식/references/content-rules/`)과 **형식 워크플로** (`9_형식/references/workflows/`).

## 양식 + 규범·자산 결합

1. 쓰기 전에 대상 양식 전체를 사전점검해 필수·선택 텍스트, 이미지 칸, 별도 첨부, 서명·날인 위치를 확인한다.
2. 성취기준 코드·법령 조항·지침 직접 인용이 필요하면 `5_규범자료/자료목록.md`에서 해당 범위를 확인한다. 없으면 그 칸을 비우고 사용자에게 묻는다.
3. 일반 내용은 `2_두뇌/팩트카드.md`와 관련 모듈에서 채운다. `6_참고자료/`를 사용한 부분에는 출처와 "두뇌 규칙 근거 없음"을 표시한다.
4. `7_개인정보이미지/자산목록.md`에서 필요한 후보만 고르고 `7_개인정보이미지/_안내.md`의 승인 범위를 확인한다. **후보를 확정하기 전에 목록이 가리키는 실제 파일이 그 경로에 있는지 먼저 확인한다** — 목록에만 있고 파일이 없으면 삽입을 시작하지 않고 알린다. 확인은 파일 존재 여부까지이며 이미지 내용을 열거나 OCR하지 않는다. 필수 개인정보 이미지·서명·날인을 발견했지만 미승인이라면 사용할 자산과 용도를 한 번 확인하고, 승인 뒤 같은 작업을 계속한다.
5. 원본 양식과 원본 이미지는 덮어쓰지 않는다. 결과는 원본 옆의 새 파일로 만든다.
6. 주요 값·이미지 종류·첨부 수·서명 위치를 확인하고, 성공한 개인정보 이미지 사용만 `7_개인정보이미지/사용기록.md`에 민감 값 없이 기록한다.

**이미지 경로의 실행 조건은 최초 요청에 서명·이미지라는 단어가 있었는지가 아니라 최종 제출본에 이미지가 필요한가와 사용 범위가 승인됐는가다.** 작업 중 필수 신분증·통장사본·증명사진·서명·날인란을 뒤늦게 발견해도 이미지 단계로 라우팅한다. 선택·모호한 이미지란은 자동 삽입하지 않고 확인하며, 필수란을 말없이 비운 채 완성본으로 보고하지 않는다.

## HWP/HWPX — Kordoc 단일 경로

실행 정본은 `npx -y kordoc@^4`이며 마지막 검증판은 4.15.6이다. 자세한 명령은 `9_형식/references/kordoc.md`를 따른다.

| 작업 | 경로 |
|---|---|
| 읽기·Markdown 파싱 | Kordoc parse |
| 기존 내용 수정 | Kordoc `patch` — 원본 포맷 유지. 편집 md는 LF 유지, exit 2면 stderr의 `SKIP` 목록 확인 |
| HWPX 양식 채우기 | Kordoc `fill --dry-run` 후 `fill` |
| 새 HWPX 생성 | Kordoc `generate`; 마크다운 이미지는 `--image-dir`로 임베드(이미지 파일명은 영문·숫자, "이미지 임베드: N개" 확인) |
| 비교·검수 | Kordoc 파싱 결과 비교·Markdown `lint`(`--munche` 필요 여부 판별)·`validate` |
| 미리보기 | 필요할 때 Kordoc `render` (svg 기본, 쪽별 png는 `--format png -d`, `.hwp`도 가능) |

- `.hwp`의 단순 내용 수정은 `patch`로 처리한다. `.hwp`에 `fill`을 쓰면 칸은 채워져도 표 테두리·글꼴·쪽 나눔이 통째로 사라진다(값만 보면 성공처럼 보인다). 양식 채우기에는 HWPX 원본을 요청한다.
- 지원되는 HWPX·HWP3·HWP5 암호 문서는 `--password`로 열고 암호를 응답·로그에 남기지 않는다. 한컴 DRM·손상 파일·지원하지 않는 구조처럼 Kordoc이 안전하게 처리하지 못하는 입력은 **그대로 둔다**. 아래 승인 이미지 배치 예외가 아니면 COM 변환, 직접 XML 편집, pack/unpack, 다른 생성기로 자동 우회하지 않는다.
- 옛 판이 남긴 저수준 XML 도구와 HWPX 골격은 열거나 호출하지 않는다. 다른 스킬(예: teacher)이 켜져 COM 변환·XML 직접 편집을 권해도 이 볼트에서는 이 파일을 따른다.
- 세부 순서는 `9_형식/references/workflows/hwpx-forms.md`를 따른다.

## 기존 문서의 승인 이미지 지정 위치 배치 — 유일한 예외

새 HWPX 생성 중 마크다운 이미지는 Kordoc `generate --image-dir`로 넣는다. 기존 HWP/HWPX의 지정 위치에 승인된 서명·도장·신분증·통장사본·증명사진·일반 사진을 넣는 일은 `9_형식/scripts/place_image.py`만 사용한다. 한컴이 실제로 그린 위치를 재서 맞추는 도구이고, `.hwp` 입력이면 한컴 COM으로 임시 HWPX를 한 번 만든 뒤 같은 방식으로 처리한다. Kordoc `seal`은 쓰지 않는다 — 4.15.6 실측에서 그림이 한글에 보이지 않거나 다른 칸에 찍혔다(`9_형식/references/kordoc.md`).

조건:

- 입력은 `.hwp` 또는 `.hwpx`, 이미지는 `.png`·`.jpg`·`.jpeg`·`.bmp`다(PDF 첨부는 먼저 PNG로). `.hwp`의 COM 변환은 **승인된 이미지 배치 작업 안에서만** 허용하며 일반 HWP 작업의 우회 경로로 쓰지 않는다.
- 사용 승인은 `7_개인정보이미지/_안내.md`를 따른다. 사용자가 특정 문서와 이미지를 직접 지정했다면 그 범위는 승인된 것이다.
- Windows 한컴, Python `pywin32`, PyMuPDF가 필요하다. 없으면 `seal`이나 다른 도구로 대신하지 않고 원본을 그대로 둔 채 필요한 조건을 알린다.
- 텍스트 값은 먼저 Kordoc으로 채우고, 이미지는 마지막에 배치한다. 양식이 별도 파일 첨부를 요구하면 문서 안 삽입으로 대체하지 않는다.
- 원본은 덮어쓰지 않는다. `.hwp` 입력도 최종본은 `*_완성본.hwpx`이며, 최종 HWPX를 COM으로 다시 저장하거나 HWP로 되돌리지 않는다.
- 명령·순서·주의점은 `9_형식/references/workflows/hwpx-forms.md` 3절이 정본이다. `9_형식/scripts/place_signature.py`는 옛 명령 호환용이고, 내부 모듈은 직접 실행하지 않는다.

## XLS/XLSX

- 읽기 전용은 Kordoc을 사용할 수 있다.
- 산출·편집은 `9_형식/references/workflows/xlsx-forms.md`를 따른다. 병합 범위는 좌상단 셀에만 쓰고 저장 후 다시 열어 검증한다.

## 저장·검증

- 원본은 덮어쓰지 않는다. 결과는 원본 옆에 `_완성본`, `_제출용`, `_검토본` 접미사로 저장하고 이름 충돌 시 번호를 붙인다.
- 새 공문 원고는 `lint`(보고서·계획서는 `--munche`) 뒤 생성하고, 일반 HWP/HWPX 결과는 Kordoc `validate`와 핵심 값 확인으로 검증한다. `lint`에는 문서 바이너리가 아니라 md/txt만 입력한다.
- 이미지 삽입 결과는 `9_형식/scripts/place_image.py`의 구조 검사와 한컴 렌더 실측을 정본으로 삼는다. 원본 비율·목표 위치·페이지 경계를 확인하고 임시 PDF는 자동 삭제한다.
- 실패한 작업은 성공처럼 보고하지 않는다. 원본과 기존 출력은 그대로 두고 실패 단계와 이유만 알린다.
