# 형식 라우팅

hwp/hwpx/xls/xlsx 산출·편집과 교사 행정문서 작업의 진입점. (기반: [teacher 스킬](https://github.com/dohyun851208/teacher), HTML 슬라이드 제외)

## 우선순위

1. **`1_두뇌/`의 개인 규칙** (글쓰기·팩트카드 등) — 항상 최우선
2. **내용 규칙** (`references/content-rules/`) — 문서 종류별 일반 관례
3. **형식 워크플로** (`references/workflows/`) — 파일 구조 보존·검증 절차

## 형식 워크플로

- `.hwp` / `.hwpx` → `references/workflows/hwpx-forms.md` (정본 절차)
  - `.hwp`는 한컴 COM이 항상 가능하다고 전제하고 묻지 말고 임시 `.hwpx` 1회 변환 → 이후 ZIP/XML 직접 편집. 최종본은 항상 `.hwpx`, `.hwp`로 재저장 금지
  - 분석 먼저: `scripts/clone_form.py --analyze`, 값 확인은 `Contents/section0.xml` 직접 검사
  - 기존 양식 채우기에 `md2hwpx.py`를 폴백으로 쓰지 않는다 (표 구조가 깨짐 — 사용자가 재설계에 동의한 경우만)
- `.xls` / `.xlsx` → `references/workflows/xlsx-forms.md` (openpyxl, 병합 범위는 좌상단 셀에만 쓰기, 저장 후 재열어 검증)
- 저수준 도구: `scripts/` (분석·치환·생성·검증·서명삽입·pack/unpack), `templates/` (공문·회의록·계획서·보고서·government·base 골격), `references/hwpx/` (XML 구조·공문서 스타일 지식)
- 발표자료·슬라이드는 형식층 담당이 아니다 (일반 능력으로 처리)

## 내용 규칙 매핑 (색인: `references/teacher-admin-rules.md`)

- 이력서·경력기술서 → `references/content-rules/resume.md`
- 공적조서·표창 추천서 → `references/content-rules/achievement-statement.md`
- 신청서·지원서 → `references/content-rules/application.md`
- 회의록·협의록 → `references/content-rules/meeting-minutes.md`
- 예산요구서·예산표 → `references/content-rules/budget-request.md`
- 그 외 공문·보고서·계획서 → `references/content-rules/common.md`

## 저장 규칙

- 원본은 절대 덮어쓰지 않는다. 결과물은 원본 파일 옆에 `_완성본`, `_제출용`, `_검토본` 접미사로 저장 (중복 시 `_완성본2`, `_완성본3`)
- 원본 없는 새 문서는 사용자가 지정한 위치에 저장. 별도 `완성본/` 폴더는 요청 시에만
- 완성된 산출물 중 판례 가치가 있는 것은 `0_원본/`에 복사해두라고 제안할 수 있다

## 인코딩·검증

- 텍스트 파일은 UTF-8로 저장. Python은 항상 `encoding="utf-8"`
- 한글 경로를 다루는 PowerShell 세션은 먼저: `chcp 65001` + `[Console]::OutputEncoding = [System.Text.Encoding]::UTF8`
- HWPX 검증은 구조 검증 + 핵심 값 확인이 기본. PDF/이미지 렌더링이나 불필요한 검증 사본을 만들지 않는다
