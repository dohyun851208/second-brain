# 회의록 내용 규칙

회의록, 협의록, 협의 결과 보고는 `references/workflows/hwpx-forms.md` 같은 형식 workflow를 먼저 따른 뒤, 이 문서의 내용 규칙을 적용한다.

## 기본 구조

- 제목: `연도 + 대상/차수 + 안건 + 회의 결과 보고` 형식으로 작성한다.
- 기본 정보: `일시`, `장소`, `참석자`, `안건`, `회의 개요`를 앞부분에 둔다.
- 본문: `회의내용`에는 안건별 협의 내용을 번호로 나눈다.
- 결론: 최종 결정, 필요성, 후속 조치를 1-2문장으로 압축한다.

## HWPX 표 양식 패턴

- 한 장짜리 회의록은 1개 표 안에 넣는 방식을 우선한다.
- 제목 행은 전체 열을 병합해 중앙 배치한다.
- `일시`와 `장소`는 같은 행에 배치할 수 있다.
- `참석자`, `안건`, `회의 개요`, `회의내용`, `결론`은 왼쪽 라벨 열과 오른쪽 내용 영역으로 나눈다.
- 내용 영역은 보통 3개 열 이상을 병합해 긴 문장이 잘리거나 지나치게 좁아지지 않게 한다.

## 작성 방식

- `회의내용`은 발언자별 대화록보다 안건별 요약을 우선한다.
- 각 안건은 `1)`, `2)`, `3)` 형식으로 나누고, 세부 근거는 `*` 또는 `가.`, `나.`, `다.`로 정리한다.
- 구매, 선정, 운영 관련 회의는 필요성, 근거, 고려사항, 실행 방안을 순서대로 쓴다.
- 실행 방안에는 품목, 예산/구입 방법, 구입처, 사용 시기, 후속 일정처럼 실제 행정 처리에 필요한 정보를 포함한다.
- URL, 업체명, 금액, 일정처럼 바뀌기 쉬운 정보는 사용자가 제공한 자료나 최신 확인 결과에 근거해 쓴다.

## 문체

- 사실 중심의 행정 보고 문체로 쓴다.
- 과장 표현보다 교육과정, 예산, 학생 안전, 형평성, 운영 가능성 같은 판단 근거를 우선한다.
- 결론은 본문을 반복하지 말고 결정 사항이 바로 보이게 쓴다.
- 참석자는 양식 폭이 좁으면 쉼표로 압축하고, 여유가 있으면 쉼표 뒤에 공백을 둔다.

## 검토

- 일시, 장소, 참석자, 안건이 빠지지 않았는지 확인한다.
- 회의내용과 결론이 서로 충돌하지 않는지 확인한다.
- 회의 결과가 실제 후속 조치로 이어질 수 있게 담당, 시기, 방법이 충분히 드러나는지 확인한다.
- 표 높이와 줄바꿈을 확인해 회의내용이 페이지 밖으로 밀리거나 겹치지 않게 한다.
